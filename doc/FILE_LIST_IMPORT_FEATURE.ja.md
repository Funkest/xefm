# ファイルリスト

[English](FILE_LIST_IMPORT_FEATURE.md) \| 日本語

ペインには、ディレクトリの代わりに **パスのリスト** を表示できます。ディスクのあちこちや複数のマシンにあるファイルを 1 つの一覧に並べ、ほかの場所と同じようにあらゆるファイル操作を行えます。

リストは XeFM の外から持ち込みます。検索はそれが一番得意なツール（Everything、`find`、`fd`、`rg -l`、`git ls-files`、ビルドログ、スプレッドシートの列など）で行い、そのパスをコピーするか、XeFM からコマンドを実行して取り込みます。

**Go → Open List** では 3 つの取り込み元からリストを開けます。それぞれキーに割り当てられるアクションになっています。

## クリップボードから

**Go → Open List → From Clipboard**（`open_list_from_clipboard`）は、クリップボードを 1 行に 1 つのパスとして読み、それらのパスをアクティブなペインに表示します。

```sh
find . -name '*.py' -mtime -1 | pbcopy        # macOS
rg -l TODO | clip                             # Windows
```

これは **Copy Full Path(s)** の逆の操作です。あちこちのファイルを選択してパスをコピーし、それを取り込むと同じ行が戻ってきます。

## コマンドから

**Go → Open List → From Command…**（`open_list_from_command`）は、コマンドを尋ねてペインのディレクトリで実行し、出力されたパスを表示します。クリップボードへパイプしてから取り込む手間が 1 回で済みます。

ダイアログはコマンドの入力欄で、その下にこれまで実行したコマンドが新しい順に並びます。

| キー | 動作 |
|---|---|
| 文字の入力 | コマンドを編集し、履歴を絞り込みます（Migemo も使えます） |
| **↓** / **↑** | 履歴の中を移動し、それぞれのコマンドを入力欄にコピーします |
| **Enter** | 履歴では、そのコマンドを選んで入力欄に戻ります。入力欄では、入力されているコマンドを実行します |
| **Esc** | 履歴では、入力していた内容に戻ります。それ以外では閉じます |
| **Shift-Delete** | 履歴では、そのコマンドを履歴から消します |

入力欄での Enter は常に入力欄の内容を実行します。履歴に `rg -l TODO` があっても、`rg -l` と入力すれば `rg -l` が実行されます。以前のコマンドを実行するには、↓ でそこまで移動して Enter を 2 回押します（1 回目で選び、2 回目で実行）。その間に内容を変えてもかまいません。[履歴付きの入力欄](NAVIGATION_DIALOGS_FEATURE.ja.md#履歴を持つ入力欄)を参照してください。

```sh
rg -l TODO
git ls-files --modified
fd -e py -E tests
es.exe -path . ext:py           # Everything, under this folder
dir /s /b *.log                  # Windows, cmd
```

Everything のコマンドラインインターフェイス `es.exe` は voidtools から別にダウンロードするもので、`PATH` に置いてください。クエリは Everything 独自の検索構文です（`ext:`、`dm:thisweek`、`size:>100mb`、`|`、`!`）。どこで実行してもインデックス全体を検索するので、ペインが表示しているフォルダーに限定するのが `-path .` です。

- コマンドはシェル（`/bin/sh`、Windows では `cmd.exe`）を通して実行されるので、パイプや引用符はプロンプトと同じように使えます。**X** の選択画面から実行するプログラムと同じ `XEFM_*` の[環境変数](EXTERNAL_PROGRAMS_FEATURE.ja.md#環境変数)が渡されます。
- 実行中は、出力された行数をダイアログが数えます。**Esc** でコマンドを止められ、そのコマンドが起動したものも止まります。
- 履歴には直近の 100 個のコマンドが残り、再起動後も保持されます。
- エラーで終了したコマンドでも出力は表示されます。`grep` や `rg` は何も一致しなかったときに、`find` は読めないフォルダーがあったときに 1 で終了します。パスを 1 つも出力しなかった場合は、ログペインに終了コードと、stderr に書かれた最後の数行が表示されます。
- コマンドは一度だけ実行されます。ファイルを削除または移動するとリストから消えますが、コマンドが再実行されることはありません。最新のリストが欲しいときは、メニューからもう一度実行してください。
- 実行できるのはローカルのディレクトリだけです。`ssh://` や `s3://` の場所を表示しているペインでは、このマシン上で実行せずに拒否します。

出力は UTF-8 として読みます。Windows では実行前にコマンドのコンソールが UTF-8 に切り替えられるので、`dir`、`es.exe` などのコンソールツールは、システムの言語にかかわらず日本語やその他の英語以外の名前をそのまま出力します。コンソールの設定を無視するプログラムの出力は、代わりにシステムのコードページで読みます。macOS と Linux では、UTF-8 として正しくない名前はバイト列のまま保持されるので、その名前のファイルも開けます。

## ファイルから

**Go → Open List → From File**（`open_list_from_file`）、またはファイルの右クリックメニューの **Open as List** は、カーソル位置のテキストファイルを 1 行に 1 つのパスのリストとして開きます。複数のリストファイルを先に選択しておくと、1 つのリストとして開きます。

リストファイルは、ファイルを指すものなら何でもかまいません。Everything からのエクスポート（**File → Export → TXT**）、ビルドログの出力ファイル一覧、プロジェクトの横に置いた `.lst` や `.txt`、コマンドの出力を保存したものなどです。

```powershell
dir -Recurse -Name *.log > logs.txt         # Windows PowerShell
```

- リストファイル内の **相対** パスは、**リストファイルがあるフォルダー** からの相対パスとして扱われます。そのため、指しているファイルの横に置いたリストは、フォルダーを移動しても使え、どちらのペインから開いても同じように読めます。
- UTF-8 と UTF-16 のファイルをどちらも読めます（Windows PowerShell 5.1 とメモ帳の「Unicode」保存は UTF-16 です）。システムのコードページのファイルも読めます。
- `ssh://` や `s3://` の場所にあるリストファイルはその場所で読まれ、相対パスの行はその場所のファイルを指します。
- リストを開いてもファイルは変わらず、ペインはファイルの変化を追いません。編集を反映するにはもう一度開いてください。
- **Backspace**（Parent Directory）でリストを抜けると、カーソルは開いたときのリストファイルの上に戻ります。そのため、リストの入ったフォルダーを順に見ていくには Backspace、↓、Enter を繰り返すだけです。

### プレイリストと Enter

**M3U プレイリスト**（`.m3u`、`.m3u8`）もリストファイルです。1 行に 1 つのパスで、プレイリストのフォルダーからの相対パスです。`#` で始まる行（`#EXTM3U`、`#EXTINF` など）は読み飛ばします。ほかのリストファイルでは、`#` で始まる行もほかと同じパスとして扱います。

**Enter** は、最初からプレイリストをリストとして開きます。**open_with_os** は引き続きプレイヤーに渡します。自分のリストファイルも Enter で同じように開くには、`FILE_ASSOCIATIONS` でその拡張子に `'list'` ハンドラーを割り当てます。

```python
{
    'pattern': ['*.m3u', '*.m3u8', '*.lst'],
    'enter': 'list',
},
```

このルールが入る前に書かれた設定には含まれていません。プレイリストで Enter を使うには上のエントリを追加してください。[ファイルの関連付け](FILE_ASSOCIATIONS_FEATURE.ja.md)を参照してください。

## キーの割り当て

3 つのアクションにはキーが割り当てられていません。割り当てるには設定に追加します。

```python
KEY_BINDINGS['open_list_from_clipboard'] = ['Ctrl-Shift-L']
KEY_BINDINGS['open_list_from_command'] = ['Ctrl-Shift-K']
KEY_BINDINGS['open_list_from_file'] = ['Ctrl-Shift-J']
```

## 読み取られる内容

以下はどの取り込み元にも当てはまります。

- 1 行に 1 つのパスです。空行は読み飛ばします。
- 行の前後の空白と、行を囲む 1 組の引用符（エクスプローラーの *パスのコピー* が書き出す `"C:\My Files\a.txt"` のようなもの）は取り除きます。
- 2 回書かれたパスは 1 回だけ表示します。
- 絶対パスと `ssh://…` / `s3://…` の場所はそのまま使い、1 つのリストに混在させられます。
- **相対** パスは、リストファイルがあるフォルダー、コマンドを実行したディレクトリ、またはクリップボードの場合は出どころがわからないのでペインが表示しているディレクトリからの相対パスとして扱います。そのように読んだ数はログの行に表示されます。コピーしたリストが別の場所から来たものなら確認してください。

それ以外は何も解釈しません。ワイルドカード、CSV の列、XeFM が開ける場所以外の URL は扱いません。

## 表示される内容

- ペインのヘッダーには、リストの名前（`Clipboard`、コマンド、またはリストファイル）と、行の名前の基準になるフォルダーが表示されます：`[Clipboard] ~/src/xefm`、`[rg -l TODO] ~/src/xefm`。ヘッダーが狭いときは、フォルダーより先に名前が短縮されます。行数は、ほかのディレクトリと同じくフッターに表示されます。
- 存在しないパスは除かれ、その数がログペインに表示されます。到達できないサーバーやドライブにあったものの数も別に表示されます。存在するものが 1 つもなければ、ペインは元のままです。
- 各行の名前は、リスト全体が共有する最も深いフォルダー（ヘッダーに表示されるもの）からの相対パスになります。1 つのプロジェクトのパスは `src/main.py` のように表示されます。2 つのドライブや 2 つのサーバーにまたがるリストは何も共有しないので、各行はパス全体を表示し、ヘッダーにはフォルダーが表示されません。
- ソート、フィルター、インクリメンタルサーチ、選択、すべてのファイル操作が行に対して使えます。削除したファイルや別の場所へ移動したファイルはリストから消えます。
- **Back**（`go_parent`）で、ペインが前に表示していたディレクトリに戻ります。リストからフォルダーを開いた場合もリストを抜けます。
- 外部プログラムは、行が共有するフォルダーから実行されます。共有するフォルダーがなければ、ペインの以前のディレクトリから実行されます。

リストはスナップショットです。後からディスクに現れたファイルは追加されず、リストを表示している間はペインの変化を監視しません。リストからフォルダーを開くか Back を押すと、通常のライブなディレクトリに戻ります。

取り込みで変わるのはペインの表示だけです。何もコピー、移動、書き込みされません。

## 自分の設定から

設定のアクションからも、[`pane.open_list()`](CUSTOMIZATION_FEATURE.ja.md#自分のファイルリストを開くpreview) を使って同じようにリストを開けます。Python で書いた検索に使えます。**Open List → From Command** と違い、アクションは UI スレッドで実行されるので、時間のかかる処理は入れないでください。
