# リモートでの編集

[English](REMOTE_EDIT_FEATURE.md) \| 日本語

SSH や S3 のペインにあるファイルで `E` を押すと、ローカルのファイルと同じようにエディターで開きます。保存するたびに、XeFM が変更をファイルの元の場所へアップロードします。

## 仕組み

1. リモートのファイルにカーソルを置き（または複数を選択し）、`E` を押します。
2. XeFM がファイルをダウンロードし、そのコピーをエディター（`TEXT_EDITOR`、または `FILE_ASSOCIATIONS` の `edit` プログラム）で開きます。
3. 好きなだけ編集して保存します。保存するたびにアップロードされ、ログにもそう記録されます：`Uploaded ssh://host/srv/app/config.yaml`。

コピーは `~/.xefm/edit/` の下の、リモートのパスに沿ったフォルダー（`~/.xefm/edit/ssh/host/srv/app/config.yaml`）に置かれるので、エディターのタイトルバーで、どのファイルを編集しているかがわかります。

保存は、vim のようなターミナルのエディターでも、VS Code のような GUI のエディターでも同じように動作します。XeFM は動いている間ずっと、約 1 秒ごとにコピーを確認しているので、独自のウィンドウで開くエディターでも、終了を待つためのオプションは必要ありません。

## ほかの誰かがファイルを変更した場合

XeFM はアップロードのたびに、開いてから（または前回アップロードしてから）リモートのファイルが変更されていないかを確認します。変更されていた場合は、上書きする前に尋ねます。

- **Overwrite** は、リモートのファイルを自分の版で置き換えます。
- **Keep Remote** は、リモートのファイルをそのままにします。自分の編集はローカルのコピーに残り、それがどこにあるかがメッセージで示されます。

## アップロードに失敗した場合

アップロードに失敗すると（接続が切れた、アクセスが拒否されたなど）、エラーの内容と、編集を保持しているローカルのコピーを示すメッセージが表示されます。何も削除されません。もう一度保存して再試行するか、ファイルを手動でコピーしてアップロードしてください。

## XeFM を終了したとき

リモートのファイルと一致するローカルのコピーは削除されます。リモートに届かなかった編集を含むコピーは残され、ログにその名前が記録されます。

すでに編集中のファイルでもう一度 `E` を押すと、アップロードされていない編集を含んでいる場合は同じコピーを開き直します。そうでなければ XeFM はファイルをもう一度ダウンロードするので、サーバーにある現在の内容から始められます。

## 制限

- **アーカイブは読み取り専用です。** zip、tar などのアーカイブの中のファイルは、表示はできますがその場では編集できません。編集するには外へコピーしてください。
- **ファイル全体をアップロードします。** 保存のたびにファイル全体がアップロードされます。この機能が想定している設定ファイルやスクリプトには、これで十分です。
- **変更の検出にはファイルの日時とサイズを使います。** 両方とも変わらないリモートの変更は検出されません。
