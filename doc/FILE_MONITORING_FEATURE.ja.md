# ファイル一覧の自動再読み込み

[English](FILE_MONITORING_FEATURE.md) \| 日本語

## 概要

XeFM は、外部のアプリケーションがファイルに加えた変更を自動的に検出して表示します。表示中のディレクトリで別のプログラムがファイルを作成、削除、変更、名前変更すると、XeFM はファイル一覧を自動的に更新します。手動で更新する必要はありません。

この機能により、表示が実際のファイルシステムの状態と同期した状態に保たれ、古い情報のまま作業することによる混乱やミスを防げます。

## 仕組み

XeFM は左右両方のペインのディレクトリを同時に監視します。外部のアプリケーションが変更を加えると、次のようになります。

- 他のプログラムが作成した**新しいファイルが自動的に表示されます**
- **削除されたファイルは**一覧からすぐに**消えます**
- **変更されたファイル**には更新後のサイズとタイムスタンプが表示されます
- **名前が変更されたファイル**には新しい名前が反映されます

自動更新の間もカーソル位置と選択は保たれるので、作業が中断されることはありません。

## 設定

### 監視の有効化と無効化

ファイルの自動監視は既定で有効です。この設定を変えるには、XeFM の設定ファイル（`~/.xefm/config.py`）を編集し、`Config` クラスの定数を設定します。

```python
FILE_MONITORING_ENABLED = True
```

自動監視を無効にするには、`FILE_MONITORING_ENABLED` を `False` にします。無効にすると、XeFM がファイル一覧を更新するのは、ディレクトリの移動や手動での更新といった操作をしたあとだけになります。

### 高度な設定項目

ほとんどのユーザーはこれらの設定を調整する必要はありませんが、細かく調整したい場合のために `~/.xefm/config.py` で使えます。

```python
FILE_MONITORING_ENABLED = True                # Enable/disable automatic reloading
FILE_MONITORING_COALESCE_DELAY_MS = 200       # Event coalescing window (milliseconds)
FILE_MONITORING_MAX_RELOADS_PER_SECOND = 5    # Maximum reloads per second (rate limiting)
FILE_MONITORING_FALLBACK_POLL_INTERVAL_S = 5  # Polling interval for fallback mode (seconds)
```

**設定項目：**

- `FILE_MONITORING_ENABLED`（既定値：`True`）- 自動監視を有効または無効にします
- `FILE_MONITORING_COALESCE_DELAY_MS`（既定値：`200`）- 複数の変更を 1 回の更新にまとめる時間幅（ミリ秒）
- `FILE_MONITORING_MAX_RELOADS_PER_SECOND`（既定値：`5`）- UI が頻繁な再描画で重くなるのを防ぐための、1 秒あたりの自動更新の最大回数
- `FILE_MONITORING_FALLBACK_POLL_INTERVAL_S`（既定値：`5`）- ネイティブの監視が使えないときのポーリング間隔（秒）

## 実行中の切り替え

XeFM の実行中に、アプリケーションを再起動せずに監視を有効または無効にできます。監視の切り替えコマンド（キーバインドを確認してください）を使うと、監視をすぐにオンまたはオフにできます。

実行中に監視を無効にすると、次のようになります。
- 自動更新はすぐに止まります
- ファイル一覧は操作のあとにだけ更新されます
- 監視はいつでも再び有効にできます

## 監視モード

XeFM はストレージの種類に応じて異なる監視方法を使います。

### ネイティブモード（推奨）

ローカルのファイルシステムでは、XeFM はオペレーティングシステムの効率のよい API を使います。
- **Linux**: inotify
- **macOS**: FSEvents  
- **Windows**: ReadDirectoryChangesW

ネイティブモードでは、最小限のリソース消費（監視するディレクトリ 1 つあたり、通常はメモリ 5MB 未満、CPU 1% 未満）で変更を即座に検出できます。

### フォールバックモード（ポーリング）

**ローカル**のパスでネイティブの監視が使えない場合、XeFM は自動的にポーリングモードに切り替わります。これは次のような場合に起こります。
- 変更通知に対応していない**ネットワークマウント**
- ネイティブの変更通知 API が使えない**ローカルファイルシステム**

フォールバックモードでは、XeFM は 5 秒ごと（設定で変更可能）に変更を確認します。ネイティブモードほど反応は速くありませんが、ローカルストレージであればどこでも監視が働きます。

### リモートとクラウドのバックエンド（監視は無効）

自動監視が働くのは、ローカルのファイルシステム上にあるパスだけです。リモートや仮想のバックエンドでは**無効**になります。スキャンするローカルのパスがないので、ポーリングでも監視できません。次のものが該当します。
- **S3 バケット**とクラウドストレージ
- SSH/SFTP 経由の**リモートファイルシステム**
- その場でブラウズしている**アーカイブ**

これらの場所ではファイル一覧は自動的に更新されません。変更を見るには手動で更新（ディレクトリに入り直す）してください。XeFM はこれらの場所ではエラーを報告せず、何も言わずに監視を行いません。

### フォールバックモードの表示

ストレージの制約やエラーのために XeFM がフォールバックモードで動作しているときは、画面に状態表示が現れます。これにより次のことがわかります。
- 監視は動作しているが、ネイティブの API ではなくポーリングを使っている
- 更新が表示されるまでに数秒かかることがある
- その種類のストレージでは、機能は正しく動作している

## 監視の対象

XeFM が監視するのは、現在の表示に**直接含まれるファイルとディレクトリだけ**です。サブディレクトリ内の変更では親ディレクトリの一覧は更新されません。そうした変更は、そのサブディレクトリに移動したときに表示されます。

2 つのペインはそれぞれ独立して監視されます。
- 左ペインでの変更は左ペインだけを更新します
- 右ペインでの変更は右ペインだけを更新します
- 各ペインはそれぞれ自分のカーソル位置と選択を保ちます

## カーソルと選択の動作

自動更新の間、XeFM は作業中の状態を保ちます。

**選択していたファイルがまだ存在する場合：**
- カーソルは同じファイルにとどまります
- スクロール位置は保たれます
- 作業は中断されずに続きます

**カーソル位置のファイルが削除された場合：**
- カーソルはその場所に繰り上がったエントリに移ります。これは、名前順、サイズ順、日付順のどれであっても、また逆順であってもなくても、ペインに実際に表示されている順序での 1 つ下の行です
- 一覧の末尾では、代わりに新しく最後になったエントリに上がります
- カーソルが見えるようにスクロール位置が調整されます

## トラブルシューティング

### ファイル一覧が自動的に更新されない

**監視が有効か確認する：**
1. 設定で `FILE_MONITORING_ENABLED` が `True` になっていることを確かめます
2. 実行中に監視をオフにしてからオンに戻してみます
3. XeFM を再起動して設定を読み込み直します

**フォールバックモードの表示を確認する：**
- フォールバックモードの表示が出ていれば、監視は動作していますがポーリングを使っています
- 変更が表示されるまでに最大 5 秒（または設定したポーリング間隔）かかることがあります
- ネットワークマウントや、ネイティブの変更通知がないローカルファイルシステムでは、これが通常の動作です

**S3、SSH、アーカイブをブラウズしていませんか？**
- リモートや仮想のバックエンドでは自動監視は無効です。監視するローカルのパスがありません
- ファイル一覧は自動では更新されません。変更を反映するにはディレクトリに入り直してください

**ログファイルを確認する：**
- XeFM は監視の動作を "FileMonitor" というコンポーネント名でログに記録します
- 監視モードを示す初期化メッセージを探してください
- 問題の原因がわかるエラーメッセージがないか確認してください

### ネットワークドライブで監視が働かない

ネットワークドライブやリモートファイルシステムは、ネイティブの変更通知に対応していないことがよくあります。XeFM はこれを自動的に検出し、フォールバックのポーリングモードに切り替えます。フォールバックモードの表示が出て、変更は数秒以内に表示されるはずです。

ネットワークドライブで監視がまったく働かない場合は、次を確認してください。
1. そのディレクトリの読み取り権限があることを確認します
2. ネットワーク接続が安定していることを確かめます
3. XeFM のログにエラーメッセージがないか確認します
4. ネットワークが遅い場合は `FILE_MONITORING_FALLBACK_POLL_INTERVAL_S` を大きくすることを検討します

### 更新が多すぎる／UI が重く感じる

非常に頻繁に変更が起こるディレクトリ（ビルドの出力ディレクトリなど）で作業していると、次のようなことが起こる場合があります。
- ファイル一覧がめまぐるしく更新される
- カーソルが飛ぶ
- 画面の反応が鈍い

**対処法：**
1. `FILE_MONITORING_MAX_RELOADS_PER_SECOND` を小さくして更新頻度を制限します
2. `FILE_MONITORING_COALESCE_DELAY_MS` を大きくして、より多くの変更をまとめます
3. 変更の多いディレクトリでは一時的に監視を無効にします
4. 変更の少ない親ディレクトリに移動します

### エラーのあと監視が働かなくなる

XeFM にはエラーからの自動回復機能があります。
- 監視に失敗すると、XeFM は再初期化を試みます（最大 3 回）
- 再初期化に失敗すると、XeFM はフォールバックのポーリングモードに切り替わります
- ポーリングも失敗すると、そのディレクトリの監視は無効になります

ログファイルにエラーメッセージがないか確認してください。よくある問題は次のとおりです。
- **Permission denied**：そのディレクトリの読み取り権限がありません
- **Too many open files**：ファイル監視数のシステム上限を超えました（Linux）
- **Network timeout**：リモートファイルシステムとの接続が切れました

回復するには次を試してください。
1. 別のディレクトリに移動してから戻ります
2. 監視をオフにしてからオンに戻します
3. XeFM を再起動します
4. システムの上限を確認します（Linux：`cat /proc/sys/fs/inotify/max_user_watches`）

### 監視数の上限を増やす（Linux）

Linux システムでは、同時に監視できるディレクトリの数に上限があります。"too many open files" エラーが出る場合は、次のようにします。

```bash
# Check current limit
cat /proc/sys/fs/inotify/max_user_watches

# Temporarily increase limit (until reboot)
sudo sysctl fs.inotify.max_user_watches=524288

# Permanently increase limit
echo "fs.inotify.max_user_watches=524288" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

## パフォーマンスについて

ファイルの自動監視は軽量になるように設計されています。
- **メモリ**：ネイティブモードで、監視するディレクトリ 1 つあたり 5MB 未満
- **CPU**：アイドル時は 1% 未満
- **ネットワーク**：ローカルのファイルシステムではネットワーク通信は発生しません

フォールバックモードのリモートファイルシステムでは、次の点に注意してください。
- ポーリングは定期的にネットワークリクエストを発生させます
- 反応の速さとネットワーク使用量のバランスを取るには `FILE_MONITORING_FALLBACK_POLL_INTERVAL_S` を調整します
- 非常に遅い接続や従量制の接続では、監視を無効にすることを検討してください

## 監視を無効にしたほうがよい場合

次のような場合は、自動監視を無効にしたほうがよいかもしれません。
- 非常に大きなディレクトリ（数千ファイル）を扱っている
- 遅いネットワーク接続や従量制の接続を使っている
- パフォーマンスの問題が起きている
- ファイル一覧をいつ更新するかを手動で制御したい
- 絶えず高頻度で変更が起こるディレクトリで作業している

監視を無効にしても、XeFM の基本機能には影響しません。移動、コピー、削除といった操作のあとには、これまでどおりファイル一覧が更新されます。

## 関連機能

- **手動での更新**：監視の設定にかかわらず、ファイル一覧はいつでも手動で更新できます
- **ディレクトリの移動**：ディレクトリを移動すると、監視も自動的についてきます
- **2 画面での操作**：2 つのペインはそれぞれ独立して監視されます

## フィードバックと問題の報告

ファイルの自動監視で問題が起きた場合は、次のようにしてください。
1. 上のトラブルシューティングの節を確認します
2. XeFM のログにエラーメッセージがないか確認します
3. 監視を無効にしてから再び有効にしてみます
4. 解決しない問題は、ログの抜粋と再現手順を添えて報告してください
