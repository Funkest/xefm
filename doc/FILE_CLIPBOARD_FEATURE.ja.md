# ファイルクリップボード

[English](FILE_CLIPBOARD_FEATURE.md) \| 日本語

ファイルを今コピーまたは切り取っておき、**次に移動した先** に貼り付けられます。3 つ目のフォルダー、別の場所へ移動した後の反対側のペイン、あるいは（macOS と Windows では）Finder やエクスプローラーにも貼り付けられます。

| アクション | キー | メニュー |
|--------|------|------|
| `clipboard_copy` | `Y`、`Ctrl-C`（macOS では `Cmd-C`） | Edit → Copy |
| `clipboard_cut` | `Shift-Y`、`Ctrl-X`（`Cmd-X`） | Edit → Cut |
| `clipboard_paste` | `G`、`Ctrl-V`（`Cmd-V`） | Edit → Paste |
| `clipboard_clear` | — | Edit → Clear Clipboard |

## クリップボードか C / M か

どちらもファイルをコピー・移動しますが、答える問いが異なります。

| | `C` / `M` | クリップボード |
|---|---|---|
| 行き先 | 今見えている **反対側のペイン** | **貼り付けるときにいる** フォルダー |
| 手順 | 1 回 | 2 回：コピーまたは切り取り、そして貼り付け |
| 届く範囲 | 2 つのペイン | どのフォルダーにも、ほかのアプリケーションにも |

`C` と `M` は、2 つのペインの間でやり取りする手早い方法のままです。クリップボードはそれ以外のすべてのためのものです。いくつものフォルダーからファイルを集めたり、どちらのペインにもまだ表示されていない場所にファイルを置いたりするときに使います。

## コピー、切り取り、貼り付け

- **Copy** または **Cut** は、選択したファイル、またはカーソル位置のファイルを取り込みます。この時点ではディスク上は何も変わりません。
- **Paste** は、それらをアクティブなペインのフォルダーにコピーします（切り取りの後なら移動します）。上書きする前には、`C` や `M` と同じダイアログで確認します。
- **コピー** は貼り付けた後もクリップボードに残るので、別の場所にもう一度貼り付けられます。**切り取り** は貼り付けると使い切られます。
- 切り取ったファイルを元のフォルダーに貼り付けても、何も起きません。
- 検索結果のペインやアーカイブの中には貼り付けられません。先にフォルダーへ移動してください。

クリップボードは、SSH や S3 上のファイル、アーカイブ内のファイルも含め、XeFM がアクセスできるあらゆるファイルを保持できます。

## 何を持っているかを確認する

- **ステータスバー** の先頭に、クリップボードの中身が表示されます：`[COPY 3]`、`[CUT 1]`、`[2 from another app]`。検索中も表示されたままなので、「行き先を探してから貼り付ける」ことができます。**クリックする** と保持しているファイルの一覧が表示され、**Paste Here** か **Clear** を選べます。**Edit → Show Clipboard…** でも同じ一覧が開きます。
- **各ペインのフッター** には、そこに貼り付けると何個の名前が競合するかが表示されます：`paste: 2 conflicts`。
- **ファイルそのもの** は、一覧に表示されるところではどこでも名前が *斜体* で表示されます。切り取ったファイルはさらに薄く表示されます。

## Finder やエクスプローラーとの連携（macOS と Windows のデスクトップアプリ）

- XeFM でローカルのファイルを **コピーする** と、システムのクリップボードにも入るので、Finder では `Cmd-V`、エクスプローラーでは `Ctrl-V` で貼り付けられます。XeFM での切り取りは、エクスプローラーにとっても切り取りです。Finder にはファイルの切り取りがないため、常にコピーになります。
- **Finder やエクスプローラーでファイルをコピー** してから XeFM で貼り付けると、それらのファイルが貼り付けられます。XeFM に戻ると、ステータスバーに `[n from another app]` と表示されます。エクスプローラーで **切り取り** したファイルは、XeFM で貼り付けると移動されます。

SSH、S3 上のファイルやアーカイブ内のファイルは、システムのクリップボードに入れられません。それらは XeFM 独自のクリップボードにのみ残ります。

**クリップボードは 1 つだけです。** コンピューター上のほかの場所と同じく、最後にコピーしたものがクリップボードの中身です。XeFM でファイルをコピーした後に、ほかのアプリや XeFM 自身のログでテキストをコピーすると、ファイルはもうクリップボードにありません。ステータスバーの表示が消え、ファイル名も斜体でなくなります。

## ターミナルと Linux では

XeFM 独自のクリップボードは、デスクトップアプリでもあらゆるターミナルでも同じように動作します。ターミナルや Linux では、システムのクリップボードとは連携しません。ターミナルのセッションは別のマシンで動いている場合があり、そこでは「システムのクリップボード」が別物になってしまうからです。

## コピーキーとログ

ログペインでテキストがハイライトされているときは、これまでどおり、コピーキーはファイルの代わりにそのテキストをコピーします。**Edit → Copy Log Selection** でも同じことができます。テキストをコピーすると、クリップボード上のファイルは置き換えられます。これはターミナルや Linux でも同じです。

## 古い config.py のキー

この機能より前に書かれた `config.py` では `Ctrl-C` が `copy_log_selection` に割り当てられていて、そのキーバインドが優先されます。`Y`、`Shift-Y`、`G` は引き続き使えます。`Ctrl-C` をクリップボードに割り当てるには、その行を次のように変更します。

```python
'copy_log_selection': [],
```

新しいコピーキーも、ログで選択範囲があるときはログのテキストをコピーします。
